# Шаблон FastAPI-застосунку для агентної розробки

Основа для нового проєкту на Python: FastAPI-застосунок без бізнес-коду, з гейтами якості, хмарним агентом Claude Code і рев'ю-ботом для PR. Шаблон стартує, проходить гейти й розгортається на Railway. Без власного коду він або показує службову сторінку, або працює заглушкою, яка тимчасово переадресовує всі запити на інший сайт.

**Звідки.** Шаблон показано на вебінарі «Архітектор замість кодера: як працює агентна розробка на Python» (21.10.2026, ведучий — Костянтин Зівенко). На ньому агенти зібрали сайт вебінару.

**Для кого.** Для тих, хто подивився запис вебінару і хоче почати власний проєкт за тим самим процесом: постановка → план → тести → код → гейти → рецензія.

## Що всередині

- **Застосунок** (`src/app/`). Фабрика `create_app`; маршрути з пакета `adapters/web/routers` підключаються без ручного переліку. Межі: `core` (сутності, порти) і `adapters` (реалізації).
- **Налаштування** зі змінних середовища (pydantic-settings), перелік — `docs/env.example`. Без обов'язкової змінної або з неправильним значенням застосунок не стартує; повідомлення називає змінну, але не показує значень.
- **Маршрути:**
  - `/` — службова сторінка з коротким значенням коміту;
  - `/healthz` (GET і HEAD) — 200, коли база відповідає;
  - `/privacy` — політика приватності;
  - `/favicon.ico`;
  - `/static/…`.
- **Сторінки:** базовий шаблон Jinja2, футер, банер cookie з Google Consent Mode v2 (`static/js/consent.js`), htmx 2.0.11 локальною копією. Юридичні тексти читаються під час старту з `docs/legal/`; без них застосунок не стартує. Зараз там нейтральні зразки — замініть їх до запуску.
- **Адаптери:**
  - база: рушій із тайм-аутами, перевірка з'єднання;
  - Cloudflare Turnstile;
  - обмеження частоти в пам'яті;
  - юридичні тексти;
  - годинник;
  - IP клієнта за проксі Railway;
  - заголовки `noindex` / `no-store`;
  - маскування токенів у журналі доступу;
  - маскування email у журналах.
- **Alembic** без таблиць: `env.py`, шаблон ревізії, порожня тека `versions/`.
- **Гейти:** pytest, ruff, mypy, pre-commit, GitHub Actions зі службовим PostgreSQL.
- **Хмарний агент і рев'ю-бот:** `.github/workflows/claude.yml` і `claude-code-review.yml` (розділ «Хмарний агент і рев'ю-бот»).
- **Правила для агента:** `CLAUDE.md`, `.claude/settings.json`. Шаблони постановки, специфікації й рецензії — `docs/templates/`; гейти курсу — `docs/gates/`.
- **Контракт** (`docs/contract.md`, `docs/legacy-schema.md`, `tests/test_contract.py`) — контракт конкретного проєкту, наведений як приклад; новий проєкт пише свій.

## Як почати проєкт

1. Створіть репозиторій із цього шаблону (кнопка «Use this template» на GitHub) або склонуйте його.
2. Напишіть `docs/requirements.md` (що будуємо) і `spec.md` за `docs/templates/spec-template.md` (як саме і в яких межах). На них спирається `CLAUDE.md`.
3. Замініть зразки в `docs/legal/` справжніми текстами; назву і опис — у `pyproject.toml`.
4. Видаліть або перепишіть разом `docs/contract.md`, `docs/legacy-schema.md` і `tests/test_contract.py`: це контракт конкретного проєкту.
5. Налаштуйте секрет, застосунок GitHub і змінні середовища (розділ «Що налаштувати»).
6. Додавайте можливості задачами за `docs/templates/task-template.md`: план → тести → код → гейти → рецензія.
7. Таблиці бази — першою ревізією: `uv run --env-file .env alembic revision -m "…"` (моделі — у `adapters/db/models.py`).

## Що налаштувати

- **Секрет репозиторію `CLAUDE_CODE_OAUTH_TOKEN`** — токен підписки Claude для хмарного агента і рев'ю-бота. Токен видає команда `claude setup-token`; додайте його в Settings → Secrets and variables → Actions.
- **Застосунок Claude на GitHub** — [github.com/apps/claude](https://github.com/apps/claude), установіть його на свій репозиторій. Без секрету і застосунку workflow агента й рев'ю-бота не працюють; CI працює й без них.
- **Змінні середовища** — перелік без значень у `docs/env.example`. Локально — файл `.env` (у git не потрапляє), на сервері — змінні сервісу.
- **Railway** (за потреби) — розділ «Розгортання на Railway».

## Як запустити локально

Потрібні Python 3.14, [uv](https://docs.astral.sh/uv/), Docker, Node.js (для тестів банера cookie).

```bash
uv sync
uv run pre-commit install
docker compose up -d                        # PostgreSQL на 127.0.0.1:55433
cp docs/env.example .env                    # заповніть DATABASE_URL та інші потрібні змінні
uv run --env-file .env alembic upgrade head
uv run --env-file .env uvicorn app.main:create_app --factory --reload
```

Для локальної бази з `compose.yaml`: `DATABASE_URL=postgresql://app@localhost:55433/app`.

## Гейти

- `uv run pytest`, `uv run ruff check .`, `uv run mypy src`.
- pre-commit запускає їх перед кожним комітом (`uv run pre-commit install` — один раз).
- CI (`.github/workflows/ci.yml`) запускає їх на кожен push у `main` і кожен PR, зі службовим PostgreSQL.
- Тести бази беруть сервер із `TEST_DATABASE_URL`, без неї — з `compose.yaml`, і працюють в окремій базі `app_test`, яку створюють і видаляють самі. Якщо сервер недоступний, ці тести пропускаються локально і падають у CI.
- Тести не звертаються до зовнішніх сервісів: їх підмінено реалізаціями з `tests/fakes.py`.
- Вихідні конфігурації гейтів курсу — `docs/gates/`: `ci.yml`, `pre-commit-config.yaml`, `pyproject-gates.toml`.

## Хмарний агент і рев'ю-бот

**Агент** (`.github/workflows/claude.yml`) береться до роботи, коли в Issue, PR, коментарі чи рев'ю є згадка `@claude`.

- Запускають його лише люди з правом запису в репозиторій. Дію відхиляє запуск від інших користувачів і від ботів.
- Агент дотримується `CLAUDE.md`. Спершу пише план у своєму коментарі, далі тести, код і гейти; наприкінці — підсумок у тому самому коментарі.
- З команд йому дозволено лише `uv sync`, `uv run pytest`, `uv run ruff check`, `uv run mypy`. Для тестів бази workflow піднімає службовий PostgreSQL.
- Одночасно для одного Issue чи PR працює один запуск; тайм-аут — 60 хвилин.

**Рев'ю-бот** (`.github/workflows/claude-code-review.yml`) рецензує кожен PR за розділом «Code Review Rules» у `CLAUDE.md` і чек-листом `docs/templates/review-checklist.md`.

- Бот лише читає диф і коментує: інлайн-коментарі до рядків і один підсумковий коментар. Код він не змінює.
- Пропускає чернетки, PR із форків (GitHub не передає їм секрети) і події від ботів.

**Обмеження безпеки.**

- Агент працює без ізоляції підпроцесів: `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` не задано. Команди, які запускає агент, бачать облікові дані Claude Code, зокрема OAuth-токен.
- Ізоляцію вимкнено свідомо: з `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` пісочниця Claude Code відхиляє запис файлів агентом (перевірено 25.10.2026), і агент не може виконати задачу.
- Захист зараз один: агента запускають лише люди з правом запису.
- Агент читає текст Issue і коментарів, а в публічному репозиторії їх може написати будь-хто. Тому для публічного форку обмежте взаємодію з репозиторієм або ввімкніть ізоляцію, коли пісочниця дозволятиме запис у робочу теку. Як її ввімкнути — у коментарі на початку `claude.yml`.

## Шаблони постановок

- `CLAUDE.md` — правила для агента: порядок роботи, межі коду, тексти, секрети, правила рецензії.
- `docs/templates/` — робочі шаблони курсу:
  - `task-template.md` — постановка задачі агентові (Goal / Context / Constraints / Done when);
  - `spec-template.md` — специфікація проєкту;
  - `review-checklist.md` — чек-лист рецензії коду від агента.
- Підсумки виконавця і рецензії між сесіями — файлами в теці `.handoff/` (поза git).

## Контракт — приклад конкретного проєкту

`docs/contract.md` і `docs/legacy-schema.md` — домовленості, за якими друга версія сайту вебінару, зібрана на цьому шаблоні, заміняла першу на тих самих адресах: посилання з уже надісланих листів, cookie, аналітика, перенесення учасників. `tests/test_contract.py` читає таблиці контракту і перевіряє, що шаблон із ним не розходиться. У шаблоні лежить версія 1 документів; пізніша — у [agent-webinar-efir](https://github.com/KonstZiv/agent-webinar-efir).

Це зразок того, як записати домовленості з попередньою системою, щоб тест тримав код і документ разом. Новий проєкт пише свій контракт або видаляє всі три файли (розділ «Як почати проєкт»).

## Режим переадресації (заглушка)

Сервісу досить двох змінних: `DATABASE_URL` і `REDIRECT_BASE_URL` (плюс ті, що ставить Railway).

- `REDIRECT_BASE_URL` — адреса `https://вузол` без шляху, параметрів і фрагмента. З нею кожен запит, крім `/healthz`, отримує `307` на `REDIRECT_BASE_URL` + той самий шлях і ті самі параметри.
- Метод і тіло запиту зберігаються.
- `Cache-Control: no-store`: ні браузер, ні проміжні кеші відповідь не запам'ятовують, тож адресу згодом можна віддати іншому сайту.
- `/healthz` працює як завжди.
- Поки `INDEXING_ENABLED` вимкнено, відповідь 307 несе `X-Robots-Tag: noindex`, як і решта відповідей. Заглушці на основній адресі сайту задайте `INDEXING_ENABLED=true`.

```bash
curl -sI "http://127.0.0.1:8000/?utm_source=test&gclid=test"
# HTTP/1.1 307 Temporary Redirect
# location: https://new.example.com/?utm_source=test&gclid=test
```

## Розгортання на Railway

- Збирач Railpack бере `pyproject.toml`, `uv.lock` і `.python-version`; запуск — `Procfile`.
- У сервісі: команда перед деплоєм `alembic upgrade head`, перевірка працездатності `/healthz`, змінні з `docs/env.example`.
- `Dockerfile` і `railway.toml` у репозиторії немає: `Dockerfile` перемкнув би Railway з Railpack на Docker.
